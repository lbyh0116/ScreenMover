# 竞品与产品定位

调研日期：2026-10-18。依据官方功能页、文档与仓库；未安装进行对照实测。功能未在文档出现不等于软件不支持。下述产品建议是基于资料和当前 ScreenMover 代码的判断，不是市场份额或性能结论。

## 主要对照

| 产品 | 官方资料中的重点 | ScreenMover 可聚焦的体验 |
| --- | --- | --- |
| Windows Snap | 系统内置分屏与布局选择。[官方说明](https://support.microsoft.com/en-us/windows/experience/snap-your-windows) | 先浏览全部目标窗口，再按屏幕拖放；减少逐个寻找标题栏的步骤 |
| PowerToys FancyZones | 自定义分区、键盘移动、跨显示器轮转及操作预览。[官方文档](https://learn.microsoft.com/en-us/windows/powertoys/fancyzones) | 相册与托盘两种入口，面向临时整理现有窗口；单纯跨屏移动不构成独有优势 |
| PowerToys Workspaces | 捕获工作区，一键启动和排列应用；支持移动已有窗口。[官方文档](https://learn.microsoft.com/en-us/windows/powertoys/workspaces) | 重点完善已打开窗口的暂存、找回和可撤销操作；保存布局本身已有成熟方案 |
| DisplayFusion | 多屏任务栏、窗口函数、事件触发器、显示器配置与窗口位置方案。[官方功能页](https://www.displayfusion.com/Features/) | 用较少设置完成识别、移动与找回；不能据此声称更省内存或更快，尚无对照基准 |
| Dual Monitor Tools / Swap Screen | 活动窗口跨屏移动、全部窗口轮转、自定义区域与光标控制。[官方说明](https://dualmonitortool.sourceforge.net/swapscreen.html) | 可视化选择、目标预告与多窗口批量操作，降低记忆快捷键的需求 |
| FancyWM | 动态平铺、面板组织、键盘操作和 Windows 原生虚拟桌面集成。[官方仓库](https://github.com/FancyWM/fancywm) | 临时调整和找回窗口的直接操作；虚拟桌面集成本身也不是独有功能 |

## 当前可表达的差异

建议定位：**窗口很多时，用一个可视化面板完成识别、跨屏移动、暂存和找回。**

已有基础是静态缩略图相册、紧凑托盘列表、显示器预览、拖放预告、批量移动和隐藏记录。这些功能组合可以构成清晰的使用路径，但不足以宣称行业首创。系统主题、免费获取、快捷键及布局保存都不应单独当作核心壁垒。

## 建议后续优先级

| 顺序 | 方向 | 用户价值 | 当前差距 |
| --- | --- | --- | --- |
| 1 | 窗口暂存区 | 按任务收起一批窗口，在一个入口明确找回；减少桌面越建越多 | 目前主要是一窗口一桌面；分组、复用、批量找回及误隐藏撤销尚未实现 |
| 2 | 可理解的屏幕路由 | 屏幕别名、一键识别、离屏窗口找回；为投影/副屏减少误投 | 需要补显示身份与恢复入口，并实测混合 DPI/断屏；不是独有功能，要靠完整体验 |
| 3 | 预览隐私控制 | 用户排除敏感应用或关闭其预览，演示前能看清哪些内容将被展示 | 尚无应用级排除策略；不能把它宣传成阻止屏幕共享泄露的安全边界 |
| 4 | 操作可信度 | 对每个批量操作说明成功/失败，可撤销并可靠找回 | 已有移动撤销和恢复记录，仍需完善部分失败和隐藏回退体验 |
| 5 | 英语界面、无障碍与架构覆盖 | 扩大实际可用人群 | 英文说明已补齐，界面国际化、键盘/读屏专项验证、x86/ARM64 仍待完成 |

建议先验证前两项的实际需求：邀请有多显示器、经常演示或同时打开大量窗口的用户，完成“找到三个指定窗口并移到副屏，再暂存和找回”的任务，观察步骤、误操作、失败原因和完成时间。没有对照测量前，不使用“最快”“最轻量”等宣传。

正式版只发布当前已实现功能，以上建议不混入发行功能清单。后续任务维护在 [开发路线](ROADMAP.md)。
