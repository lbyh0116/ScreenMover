日期：2026-10-18。范围：源码与生命周期检查、NuGet 已知漏洞查询、无界面回归、截图组件的原生资源重复测试。没有使用 computer use，没有把这些检查扩展成“整个程序无泄漏/无漏洞”的保证。

## 结构调整

- 从 MainWindow.Options 拆出设置页面协调器、SettingsEditor、HotkeyPicker 和 SettingsCommit。编辑器管理控件，提交服务集中处理两个快捷键、设置文件及启动项的回退。
- 截图移到独立 CaptureWorker 控制台进程，复用 SnapshotService 及主发布目录的自包含 .NET 运行时，不加载 WinUI，也不需要重复捆绑第二套运行时。
- 版本号集中在 Directory.Build.props，统一主程序、截图组件与诊断项目。

## 已修复的资源和边界问题

1. 旧截图进程会初始化 WinUI；已换成轻量进程。父进程限制图像尺寸、完整帧长度和附加字节，并发排空错误输出，取消时结束进程再完成管道清理。
2. 窗口图像缓存最多 64 个，淘汰时同时清除模型引用；覆盖了“字典已删但模型仍引用图像”的情况。按最大 360×360×4 计算，64 个原始像素约 31.6 MiB，这不是应用总内存上限。
3. 清理拖拽历史选择、拖拽图像和隐藏快捷面板的旧控件/图像引用；游标、定时器、事件订阅与原生钩子按生命周期释放。
4. 事件钩子构造中途失败时会撤销已经成功的注册，避免遗留回调；监听不可用时基础功能使用轮询，避免整个软件无法启动。
5. 操作历史只在内存加载最近 500 条，尾部读取限定 2 MiB；活动文件到 4 MiB 后归档保存。异常长记录截断，历史归档不自动删除。
6. 单实例 IPC 限当前用户、单条消息最多 32 字符；异常连接有重试退避，取消源在监听任务结束后释放。
7. 操作、截图、撤销及选择恢复加强 PID/启动时间/窗口句柄身份关联，防止进程与句柄复用后误作用到替代窗口；不绕过窗口捕获保护或 Windows 权限。
8. 设置自动保存保留失败回退：第二个快捷键冲突、磁盘失败或启动项失败不能悄悄覆盖先前有效绑定。回退本身失败会显示不同错误，避免声称文件一定已恢复。
